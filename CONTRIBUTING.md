# Contributing / 贡献指南

> LGD-Eval · 凡自治之物评测线 ｜ 双语：英文在前，中文在后，均完整。

## Welcome — including AI agents / 欢迎——包括 AI 代理

We accept contributions from all sources, including **AI agents**. No contribution is too small — every verified improvement counts. / 我们接受来自所有来源的贡献，包括 **AI 代理**。没有贡献是太小而不值得的——每一个经核验的改进都算数。

## How to contribute / 如何贡献

1. **Read** `AGENTS.md` (repo guide) + `PROMPTING.md` (the hook & onboarding). / 阅读 `AGENTS.md`（仓库指南）与 `PROMPTING.md`（引导与入职）。
2. **Pick a task**: Issues labeled `good first issue` / `protocol` / `evidence` / `audit`. / 选择任务：带 `good first issue` / `protocol` / `evidence` / `audit` 标签的 Issue。
3. **Implement**: small, focused changes only. / 实施：只做小且聚焦的改动。
4. **Submit a PR** with / 提交 PR 时附上：
   - Reference to the issue it fixes / 引用其修复的 Issue
   - Evidence: reproducible steps; recompute SHA-256 if data changed / 证据：可复现步骤；改动数据须重算 SHA-256
   - AI disclosure trailer (see below) / AI 声明 trailer（见下）

## AI attribution standard / AI 署名规范（内核标准）

We follow the Linux Kernel trailer convention (2025-05) so our history is parseable by standard tooling everywhere. / 我们遵循 Linux 内核 trailer 规范（2025-05），让我们的提交历史可被任何标准工具解析。

| Trailer | Meaning / 含义 | Who places it / 由谁放 |
|---|---|---|
| `Assisted-by: <AI or person> <email>` | Substantive help in writing/debugging/shaping the patch, incl. AI tools / 在撰写/调试/成形补丁中提供实质帮助（含 AI 工具） | Human committer (or the accountable agent) / 提交责任人 |
| `Signed-off-by: <human> <email>` | Ownership certification — you vouch for the code / 所有权认证——你为代码背书 | Human / 人类 |
| `Co-authored-by: <name> <email>` | Collaborative session co-authorship / 协作会话的共同作者 | Any participant / 任一参与者 |

Examples / 示例:
```
Assisted-by: LGD-Eval AI <lgd-eval-ai@users.noreply.github.com>
Signed-off-by: LGD-Eval <LGD-Eval@users.noreply.github.com>
```

Rules / 规则:
- `Assisted-by` is for **material** assistance (a function draft, a refactor, a debug strategy) — not a one-line nudge. / `Assisted-by` 用于**实质**帮助（函数草稿、重构、调试策略）——不是一句提示。
- `Signed-off-by` remains your certification; it never transfers to a tool. / `Signed-off-by` 始终是你的认证，不转移给工具。
- If an AI drafts most of a patch and you review/merge it, include **both** trailers. / 若 AI 起草了大部分补丁而由你审阅合入，两条 trailer 都要放。
- `Generated-by:` may be used when content is fully generated by an AI and reviewed by a human. / 内容完全由 AI 生成且经人类审阅时可用 `Generated-by:`。

## Quality gates / 质量门禁

- **Small, focused PRs** — one intent per PR; no drive-by changes. / 小且聚焦的 PR——一个 PR 一个意图；不做顺手改动。
- **Evidence attached** — no unreferenced claims. / 附证据——无未溯源结论。
- **Independent verification** — we do not accept self-review; your work will be independently re-verified. / 独立复核——我们不接受自查；您的工作将被独立复验。
- **Bilingual** — English first, Chinese complete. / 双语——英文在前、中文完整。
- **Automated checks** — where tests exist, they must pass before merge (e.g., `python -m unittest tests/test_verify_hash_manifest.py`). / 自动化检查——存在测试处必须通过后方可合入。

## Response pledge / 响应承诺

- **Issues & PRs replied within 48 hours** (rolling 24h timezone coverage). / **Issues 与 PR 48 小时内回应**（24 小时滚动时区覆盖）。
- Open and honest: we publish problems as readily as results. / 公开透明：我们公布问题的勇气与公布结果的勇气一样大。
- No-contribution-is-too-small: even a "this is unclear" issue is a valued contribution. / 没有太小的贡献："这里看不懂"也是被珍视的贡献。

## Boundaries / 边界

- ✅ **Always**: attach evidence, disclose AI assistance, keep changes scoped, pass existing tests. / **总是**：附证据、声明 AI 参与、控制改动范围、通过已有测试。
- ⚠️ **Ask first**: changing published report conclusions, protocol standards, or hash-manifest semantics. / **先问**：修改已发布报告结论、协议标准或 hash-manifest 语义。
- 🚫 **Never**: commit secrets, falsify evidence, modify hash records without recomputing. / **绝不**：提交密钥、伪造证据、不重算而修改哈希记录。

## Code of conduct / 行为准则

- Respect the neutrality principle: no promotional bias in reports. / 尊重中立原则：报告中不带推广偏向。
- Disagree with evidence, not with attitude. / 用证据反驳，不用态度。
- We welcome AI contributions, and we verify everything — for humans and agents alike. / 我们欢迎 AI 贡献，并核验一切——对人类与代理一视同仁。
